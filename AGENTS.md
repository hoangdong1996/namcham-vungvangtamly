# Project rules

- The 5 CHẠM logo is served from the Lovable CDN asset (`/__l5e/assets-v1/...`), referenced only through `src/lib/logo.ts` with its pointer JSON at `src/assets/logo-5-cham.asset.json`; never re-upload, copy, or hotlink the logo elsewhere. The favicon is a 64px square crop at `public/favicon.png`.
- This project replicates the "5 CHẠM – Vững vàng tâm lý" school site (Trường THPT Tây Tiền Hải). All user-facing copy is Vietnamese and must match the original site's wording; page titles follow the pattern "Chạm N – <Tên> | 5 CHẠM – Vững vàng tâm lý".
- Design tokens (green `--primary`, plum `--plum`, pink `--pink-band`/`--pink-chip`, mint `--mint`) live in `src/styles.css`; fonts are Baloo 2 (display) + Quicksand (body) loaded via `<link>` in `src/routes/__root.tsx`. Never hardcode colors in components.
- Chạm 2 interactive activities (emotion mirror, screen scenarios, perspective lens, notebook) are isolated in `src/components/cham-two` (Chạm 3 and Chạm 5 activities likewise in `src/components/cham-three` and `src/components/cham-five`); personal answers use component state only, without browser persistence or network submission, to preserve session privacy and leave other pages unchanged.
- Chạm 5's companion journey uses its own content module and component; cross-section contact buttons dispatch the supporter ID to the existing map, so contact guidance has one source of truth.
- The help-source directory is a separate session-state component on the existing Chạm 5 route; the heart navigation uses its section anchor while Chạm 5 navigation keeps the original journey, preventing duplicate pages or replacement of activities.
- The document library (/tai-lieu) reads entries from `src/components/library/data.ts`; open/download buttons render only when a real link or file exists, so no fake documents are shown.
- "Tài liệu của tôi" on /tai-lieu stores files in the private `my-documents` bucket + `my_documents` table; reads are owner-only (signed-in, `uploaded_by`/`owner_id` = caller), uploads/deletes also require the `admin` role, so private files never reach anonymous or other accounts.
- The five-touch signature mark lives in `src/components/home/five-touch-mark.tsx` (animated SVG, reduced-motion safe); reuse it instead of drawing new logos. Homepage journey progress is session-state only, so nothing personal is stored.
- The existing model card row is isolated in `src/components/home/model-connections.tsx`; a disconnecting IntersectionObserver gates its one-shot animation, preserving card layout and typed Chạm navigation independently of the signature logo.
- The Chạm 1 AI pressure-share (`src/lib/support-suggest`, `src/components/cham-one`) suggests only catalog exercise IDs and never stores or logs student text; disable SDK error-body logging and use shared `src/lib/support-safety.ts` guidance/error presentation across safety areas, keeping adult support consistent and raw errors out of the UI. Transport retries require a fresh user click; no automatic resubmission.
- The homepage ending is isolated in `src/components/home/last-touch*` and `open-letter.tsx`; its local choices/draft never use persistence or network and delivery is disabled, keeping the existing activities and shared Footer independent.
- Root error and not-found content rely on the existing shared shell for Header/Footer rather than rendering another pair, preventing duplicate navigation and Footer on unavailable pages.
- Adult learning lives in `src/components/adult-companion` on `/dong-hanh`; its homepage entry precedes LastTouch, all practice is component-state only and resources reference existing library entries rather than duplicating storage, preserving student activities and document permissions.
- The Chạm 1 emotion map is an isolated local component with a pure suggestion catalog; closing unmounts its practice state, preventing disclosure persistence and keeping AI and other activities independent.
- Website star ratings live in `src/components/rating` (one homepage section after LastTouch); the `website_ratings` table has RLS with no policies and is reached only through security-definer RPCs (submit with UNIQUE session_id, public summary, admin-only per-star stats), so raw rows and visit IDs never reach browsers. The visit ID lives in sessionStorage (same tab survives reload; new tab/visit = new ID) and is never tied to identity.
